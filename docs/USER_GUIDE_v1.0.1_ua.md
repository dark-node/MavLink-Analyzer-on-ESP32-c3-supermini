# MavLink Analyzer — інструкція користувача v1.0.1

| | |
|---|---|
| Версія прошивки | **1.0.1** (release) |
| Плата | ESP32-C3 Super Mini |
| Веб-інтерфейс | http://192.168.4.1 |
| Підключення дротів | [Техспецифікація §2](TECHNICAL_SPECIFICATION_v1.0_ua.md#2-апаратна-частина) |

---

## 1. Призначення

**MavLink Analyzer** стоїть між **політним контролером (FC)** і **приймачем** (або іншим UART MAVLink-пристроєм):

1. **Прозорий міст** — усі MAVLink-кадри проходять між FC і приймачем без змін (arm, RC, телеметрія).
2. **Журнал у браузері** — записується і показується лише потік **від приймача до FC** (команди, місії, керування). Телеметрія **від FC до приймача** через міст іде, але **в лог не потрапляє**.

---

## 2. Безпека та обмеження

- UART ESP32-C3 — **лише 3.3 V**. Не підключайте 5 V TTL без перетворювача рівня.
- Обов’язкова **спільна GND** між FC, ESP і приймачем.
- Wi-Fi точки доступу **не має інтернету** — лише зв’язок з вашим телефоном/ноутбуком.
- Температура на екрані Monitor — **температура кристала ESP**, не повітря; при тривалій роботі з Wi‑Fi може бути 70–80 °C.
- Кнопка **Exit** вимикає Wi‑Fi і переводить плату в **deep sleep** — для нового сеансу потрібно **вимкнути і знову увімкнути живлення**.

---

## 3. Підключення (коротко)

Детально: **[техспецифікація §2](TECHNICAL_SPECIFICATION_v1.0_ua.md#2-апаратна-частина)**

| Зв’язок | Від | До ESP |
|--------|-----|--------|
| FC → ESP (прийом) | FC **TX** | **GPIO 20** (UART0 RX) |
| ESP → FC (передача) | FC **RX** | **GPIO 21** (UART0 TX) |
| Receiver → ESP | Receiver **TX** | **GPIO 4** (UART1 RX) |
| ESP → Receiver | Receiver **RX** | **GPIO 5** (UART1 TX) |
| Земля | GND усіх пристроїв | **GND** ESP |

Формат UART: **8N1**, швидкість за замовчуванням **115200** (має збігатися з FC і приймачем).

## 4. Перше вмикання

### 4.1. Живлення та USB

1. Підключіть дроти згідно з таблицею вище.
2. Подайте живлення на ESP (USB-C або ваше джерело 3.3 V).
3. Опційно: USB до ПК, Serial Monitor **115200** — має з’явитися рядок `BOOT OK`.

### 4.2. Wi‑Fi

| Параметр | За замовчуванням |
|----------|------------------|
| SSID | `MavLink-Analyzer` |
| Пароль | `12345678` |
| IP аналізатора | `192.168.4.1` |

1. На телефоні або ноутбуці відкрийте Wi‑Fi і підключіться до `MavLink-Analyzer`.
2. У браузері введіть: **http://192.168.4.1**  
   (автовідкриття сторінки після підключення до Wi‑Fi не передбачене — адресу потрібно ввести вручну).

### 4.3. Перший сеанс

Після увімкнення живлення пристрій у стані **RUN** — міст уже працює.

1. Переконайтеся, що на сторінці зелений статус WebSocket («Live stream connected»).
2. У блоці **MAVLink log** з’являться рядки з напрямком **RCVR→FC**, якщо приймач надсилає дані.
3. Перевірте на FC/приймачі: arm, RC, телеметрія мають працювати як без аналізатора.

## 5. Веб-інтерфейс

### 5.1. Шапка

- **MavLink Analyzer** — назва.
- Індикатор **RUN** / **STOP** (кольорова мітка).
- **EN / UA** — мова інтерфейсу (зберігається в браузері).
- **Debug** — додаткові технічні блоки (пам’ять, сирий JSON статусу). У звичайній роботі можна вимкнено.

### 5.2. Кнопки керування

| Кнопка | Дія |
|--------|-----|
| **STOP** | Зупинити міст і UART; лог заморожений; можна змінювати налаштування P1–P5, P7–P8 |
| **START** | Застосувати налаштування з форми і знову запустити міст |
| **Save log** | Завантажити файл `MavLinkLog_N.txt` з буфера ESP (до 100 останніх кадрів) |
| **Browser log** | З’являється, якщо увімкнено P6 — зберегти повний лог з пам’яті браузера |
| **Exit** | Завершити сеанс: Wi‑Fi вимкнено, deep sleep; потрібен новий цикл живлення |

### 5.3. Live stats

Оновлення кожні **5 секунд**:

| Показник | Зміст |
|----------|--------|
| Log /s | Валідні кадри в лог (RCVR→FC) за секунду |
| Telem /s | Кадри телеметрії FC→приймач (лише лічильник, не в логу) |
| Bridge B/s | Байти через міст (обидва напрямки) |
| CRC /s | Помилки CRC на лінії приймача→FC |

### 5.4. Налаштування (P1–P8)

| ID | Назва | Опис |
|----|--------|------|
| P1 | MAVLink | `auto`, `v1` або `v2` — фільтр версії для логу |
| P2 | Baudrate | 9600 … 921600; однакова на обох UART |
| P3 | Parsing | **Off** — hex payload; **On** — розбір відомих повідомлень |
| P4 | Filter HB | **On** — HEARTBEAT (msgid 0) не потрапляє в лог (міст не чіпає) |
| P5 | Passthrough | **On** — міст увімкнено; **Off** — UART не пересилає (діагностика) |
| P6 | Browser log | Зберігати кожен рядок логу в localStorage браузера |
| P7 | Wi‑Fi SSID | 1–32 символи |
| P8 | Wi‑Fi password | 8–63 символи |

**Зберегти** — запис у пам’ять ESP (NVS).  
**Reboot** — перезавантаження (для застосування Wi‑Fi після збереження).  
**Reset** — заводські значення P1–P8.

### 5.5. Режим Parsing On — які повідомлення розбираються

У логу з’являються розгорнуті поля для:

| msgid | Назва |
|-------|--------|
| 0 | HEARTBEAT |
| 24 | GPS_RAW_INT |
| 30 | ATTITUDE |
| 33 | GLOBAL_POSITION_INT |
| 74 | VFR_HUD |
| 75 | COMMAND_INT |
| 76 | COMMAND_LONG |
| 152 | MEMINFO (ArduPilot) |
| 163 | AHRS (ArduPilot) |
| 253 | STATUSTEXT |

Інші валідні MAVLink-кадри з лінії RCVR→FC показуються як **raw** (hex payload).

### 5.6. Debug (опційно)

При увімкненому **Debug**:

- **Memory & flash** — RAM, прошивка, буфер логу, NVS.
- **API status (raw)** — JSON `GET /api/status`.

У **release**-прошивці (v1.0.1) емуляція пакетів недоступна — лише реальний UART.

## 6. Типові сценарії

### 6.1. Зміна швидкості UART

1. **STOP**
2. **Baudrate** — оберіть значення як у FC
3. **Save**
4. **START**

### 6.2. Зміна Wi‑Fi

1. **STOP**
2. Введіть новий **SSID** і **пароль** (≥ 8 символів)
3. **Save**
4. **Reboot**
5. Підключіться до нової мережі Wi‑Fi

### 6.3. Зберегти лог польоту

1. Під час або після польоту відкрийте http://192.168.4.1
2. **Save log** — файл `MavLinkLog_0.txt`, далі `MavLinkLog_1.txt` …
3. Лічильник скидається після повного вимкнення живлення

### 6.4. Повний лог у браузері (P6)

1. У **STOP** увімкніть **Browser log** (або в RUN — P6 діє одразу)
2. Після сесії: **Browser log** → файл `MavLinkBrowserLog.txt`
3. При переповненні localStorage з’явиться попередження — вимкніть P6 або очистіть дані сайту

### 6.5. Завершення роботи

1. **Exit** → підтвердження
2. Wi‑Fi зникне; плата у deep sleep
3. Вимкніть живлення; для наступного разу — увімкніть знову

## 7. Що нормально, а що перевірити

| Спостереження | Пояснення |
|---------------|-----------|
| У логу немає ATTITUDE/GPS від FC | **Нормально** — лог лише RCVR→FC |
| Telem /s > 0, а лог порожній з боку FC | **Нормально** |
| HEARTBEAT не видно в логу | **Нормально** при Filter HB = On |
| CRC /s > 0 інколи | Можливі пошкоджені кадри на лінії; перевірте дроти і baud |
| Темп. попередження в UI | Внутрішня температура ESP ≥ 80 °C — покращіть охолодження |
| Після Exit немає Wi‑Fi | **Нормально** — потрібен power cycle |

## 8. Прошивка та збірка (для сервісу)

```bash
pio run -e release -t upload
pio device monitor
```

За замовчуванням у проєкті активне середовище **release** (реальний UART, v1.0.1).
